# Synthetic Student Research Validation

The synthetic student validation framework exercises the current production
contracts without introducing a second formative runtime:

```text
assessment evidence
-> initial student profile
-> FormativeConversationSession
-> formative_conversation_agent
-> profile transition
-> teacher trajectory
-> research export
```

It does not define expected learning outcomes, fixed tutor messages, activity
sequences, or rule-based profile changes. A transition is reported only when
the production formative conversation agent recommends one and the existing
profile-transition service persists it.

## Personas

The built-in catalog includes:

- `correct_shallow`
- `confident_misconception`
- `correct_low_confidence`
- `overconfident_incorrect`
- `disengaged`
- `high_performing_extension`

Each strict persona contract defines three assessment responses, reasoning,
confidence, observable timing/revision/navigation behavior, and two to ten
student conversation turns. Persona JSON cannot add expected outcomes, target
profiles, or tutor responses.

Use `--persona-file <path>` to replace the built-in catalog with a JSON object
or array that satisfies the same contract. Use `--personas <id,id>` to select a
subset.

## No-provider plan

The default command writes a plan artifact and makes no provider calls:

```bash
npm run student:synthetic-research-validation -- --mode=plan
```

The deterministic integration smoke validates database persistence,
telemetry, teacher projection, export joins, export reproducibility, and the
OpenAI transport guard. Its tutor output is contract-test infrastructure and
is explicitly not a pedagogical evaluation:

```bash
npm run student:synthetic-research-validation-smoke
```

## Explicit live run

A live run uses the approved production `student_profiling_agent` and
`formative_conversation_agent`. It requires both an environment opt-in and a
command-line confirmation:

```bash
SYNTHETIC_RESEARCH_LIVE_CALLS_ENABLED=true \
npm run student:synthetic-research-validation -- \
  --mode=live \
  --confirm-live-provider-calls
```

The normal operational role configuration, approval bundle, usage limits, and
`RESEARCH_PSEUDONYMIZATION_KEY` must already be valid. A fallback-derived
initial profile is rejected as live validation evidence. Use `--cleanup` to
delete only the generated synthetic fixture after artifacts are written;
otherwise synthetic sessions remain available for teacher review.

Artifacts are written under:

```text
.data/synthetic-student-validation/
```

The JSON report excludes prompts, raw provider payloads, credentials, internal
database IDs, and provider request IDs. The accompanying ZIP is generated by
the existing analysis-ready research export service.

## Interpretation limits

- Scripted student messages do not adapt semantically to each tutor response.
- A run validates orchestration and evidence traceability; it does not establish
  psychometric validity or instructional effectiveness.
- A null final transition means available conversation evidence did not produce
  a persisted validated transition.
- Comparisons across personas require repeated runs and a separate analysis
  protocol; these personas are test conditions, not learner typologies.
